Prédiction des ventes publicitaires et déploiement d'une API

Problématique marketing : Comment prédire les ventes d'une entreprise à partir de ses budgets publicitaires (TV, radio et presse) ?

Objectif : Comparer plusieurs modèles de régression, puis mettre le modèle retenu en production sous la forme d'une API conteneurisée.

Python Scikit-learn XGBoost FastAPI Docker Advertising Dataset (Kaggle)

Modélisation

  • 200 observations, séparées en 160 pour l'entraînement et 40 pour le test.
  • Trois modèles comparés : régression linéaire (R² = 0,899 ; RMSE = 1,78), Random Forest (RMSE = 0,77) et XGBoost (R² = 0,975 ; RMSE = 0,88).
  • Modèle déployé : XGBoost, sauvegardé avec joblib.
  • Lecture métier : dans la régression linéaire, le coefficient de la radio (0,19) est environ 4 fois celui de la TV (0,045), et celui de la presse est proche de zéro (0,003).

API et conteneurisation

  • FastAPI (app.py) : route /predict qui reçoit les 3 budgets et renvoie les ventes prévues, avec une documentation interactive sur /docs.
  • Docker (Dockerfile) : image Python 3.10 slim, dépendances dans requirements.txt, serveur uvicorn sur le port 8000.

Prédiction des défauts de paiement (classification binaire)

Problématique métier : Une banque souhaite repérer à l'avance les clients de cartes de crédit susceptibles de ne pas rembourser, afin de limiter ses pertes.

Objectif : Estimer la probabilité de défaut d'un client à partir de son profil, de ses retards de paiement et de ses montants de facture.

Python Régression logistique Classification Default of Credit Card Clients (UCI)

Méthode

  • 30 000 clients, dont 22,1 % en défaut : une classe minoritaire.
  • Séparation 80 / 20 stratifiée et standardisation des variables.
  • Régression logistique avec pondération de la classe minoritaire, pour mieux détecter les défauts.
  • Évaluation : matrice de confusion, précision, rappel et courbe ROC.
Voir le notebook

Résultats et recommandation

  • AUC de 0,71 : le modèle sépare correctement les profils, sans être très discriminant.
  • Il détecte 62 % des défauts réels (rappel), avec une précision de 37 % sur cette classe.
  • Signal le plus fort : l'historique de paiement du mois précédent. Une limite de crédit élevée réduit le risque.
  • Piste : utiliser le score pour prioriser les contacts clients, avec des seuils à calibrer selon la politique de risque de la banque.

Prévision des ventes avec Prophet (séries temporelles)

Problématique métier : Une chaîne de magasins souhaite anticiper ses ventes pour ajuster ses stocks et ses commandes fournisseurs.

Objectif : Modéliser la tendance et les cycles des ventes quotidiennes, puis prévoir les 90 prochains jours.

Python Séries temporelles Prophet Store Sales (Kaggle)

Méthode

  • Agrégation des ventes quotidiennes de tous les magasins.
  • Modèle Prophet avec saisonnalités hebdomadaire et annuelle, et prévision à 90 jours avec zone d'incertitude.
  • Validation sur les 30 derniers jours : erreur moyenne d'environ 69 750 ventes par jour, soit 8,4 %.
  • Ajout des jours fériés du pays pour affiner le modèle.
Voir le notebook

Résultats

  • Tendance à la hausse sur toute la période, de 2013 à 2017.
  • Cycle hebdomadaire : le dimanche est le jour le plus fort, suivi du samedi, et le jeudi le plus faible.
  • Pic annuel en fin d'année, autour de Noël.
  • Usage : adapter les effectifs au calendrier hebdomadaire et renforcer les stocks avant les fêtes.

Prédiction des prix immobiliers (régression linéaire)

Problématique métier : Estimer la valeur d'un logement à partir de ses caractéristiques et de son quartier.

Objectif : Entraîner une régression linéaire multiple, mesurer sa précision et identifier les variables qui pèsent sur le prix.

Python Scikit-Learn Régression linéaire Boston Housing

Méthode

  • Matrice de corrélation, puis régression linéaire sur les variables numériques (séparation 80 / 20).
  • Évaluation : R², RMSE, MAPE et analyse des résidus.
Voir le notebook

Résultats

  • R² de 0,63, avec une erreur moyenne de 5,2 k$ (MAPE de 18,6 %).
  • Une pièce supplémentaire augmente le prix médian d'environ 4,8 k$.
  • La pollution (NOX), la distance aux centres d'emploi, le ratio élèves/enseignants et la part de population défavorisée pèsent négativement sur le prix.

Segmentation clients (clustering non supervisé)

Problématique métier : Un centre commercial souhaite regrouper ses clients en segments homogènes pour adapter ses actions marketing.

Objectif : Segmenter 200 clients selon leur revenu annuel et leur score de dépense, sans étiquettes préalables.

Python K-Means / CAH / DBSCAN Clustering Mall Customers (Kaggle)

Méthode

  • Standardisation du revenu et du score de dépense.
  • Méthode du coude pour choisir 5 groupes, puis K-Means.
  • Comparaison avec une classification hiérarchique (dendrogramme) et une version 3D incluant l'âge.
  • DBSCAN pour repérer les clients atypiques.
Voir le notebook Colab

Les 5 profils identifiés

  • Moyens : revenu et dépense moyens (environ 55 k$ et score 50), le groupe central.
  • Premium : revenu et dépense élevés (environ 87 k$ et score 82).
  • Dépensiers à petit budget : revenu faible, dépense élevée (environ 26 k$ et score 79).
  • Potentiel inexploité : revenu élevé, dépense faible (environ 88 k$ et score 17).
  • Prudents : revenu et dépense faibles (environ 26 k$ et score 21).
  • Piste : fidéliser les premium et activer le groupe à fort revenu mais faible dépense.
